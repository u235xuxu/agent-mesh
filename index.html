把散在多台机器上的 Agent
连成一张网

不共享记忆，但共享方法。不互相干扰，但能互相干活。

Connect independent AI agents across machines, OSes and networks — without leaking each other's context.

问题

你有 Mac、有 Windows、有一台海外 VPS、可能还有台 mini。每个都能装 Agent，但它们是四个孤岛：

  • 笔记本休眠了，上面的定时任务就断了
  • VPS 上有能力，但你的助手连不上
  • 同一个人两个助手，各记各的
  • 想跨机器干一件事，得手动 SSH 一趟趟跑

现有多 Agent 框架基本假设「一台机器 / 同一个 Docker 网络」。一旦跨 OS、跨 NAT、跨运营商，全部失效。

核心设计：Git 当消息总线

┌──────────────────────┐ │ Git remote │ ← 唯一必须所有节点都能到达的地方 │ (Gitea / GitHub) │ └──────────┬───────────┘ │ ┌─────────────┼─────────────┐ │ │ │ ▼ ▼ ▼ 节点A 节点B 节点C pull/处理/push 同左 同左

为什么不用 Redis / MQTT / WebSocket？因为它们都要求「一个所有节点都能主动连上的中心」。跨 NAT 的家用机器连不进去。

这四台机器可能任何两台之间都不通，但每一台都能 git push。

核心创新：隔离式知识交换

大多数「多 Agent 共享记忆」是共享一个记忆池。一旦两个 Agent 服务不同的人，立刻出事——隐私穿透、判断污染、规则打架。

这套方案：目录分层 + 服务端 Git hook 强制。

repo/
├── _shared/       # 双方读，只有 admin 写
├── alice/         # 只能 alice 写
└── bob/           # 只能 bob 写

越权推送直接被拒，不是靠约定：

remote: ❌ 拒绝：alice 只能修改 alice/ 目录
remote:    违规文件: bob/messages/for-alice/hack.md
